## 1. 交付范围

- 不同工作区保有独立 Runtime，可同时对话、读写、执行、排队及等待审批；切换查看不结束原任务。
- 对话入口可选已有工作区或打开目录，再创建或切换其对话；页面持续显示真实执行目录。
- 同一工作区仍只允许一个执行对话；不迁移已有对话绑定，不实现同目录多写者。
- 状态库由宿主共享，重启恢复只在首次打开执行一次；不改存储引擎与 schema。
- IPC v9 将工作区与对话身份绑定到请求；旧页面动作拒绝，旧请求只保留兼容单工作区测试入口。
- Provider 继续全应用配置，变更时所有工作区必须空闲；仅 main 内共享仅内存秘密，不进入 DTO。
- 全应用最多两个在途模型请求，汇总请求数和已返回 usage；未返回 usage 不写成零，不虚构费用。
- 最多八个驻留工作区。路径经 realpath；别名复用同一 Runtime，重叠目录及共享 Git 元数据拒绝并发驻留。
- 提供工作区状态、选择、显式关闭；单工作区停止/关闭只处理所属任务，整个应用退出处理全部 Runtime。
- 重启不自动发送队列或恢复执行。权限、审批目标、审计、取消与进程清理红线不变。

### 4.3 首失败及修正

首轮定向测试发现 Gateway 的旧 usage 缺省零值不能代表上游已报告。
增加可选 usageReported，未报告时汇总保留 UNKNOWN，不累计伪造零值。
回归发现模拟重启与显式关闭的不同要求，关闭取消只在宿主明确传 cancelPending 时执行。
受限 Runtime 同步补全 main 内 Provider 状态接口，继续拒绝执行。
旧 Schema/Preload 源码断言按 v9 与绑定入口更新，历史恢复用例保持原判据。
真实产品首轮驱动只等待 completed，但写文件结果为 completed_with_warnings；按既有终态合同修正驱动。
两次布局驱动失败后暂停整批，最小几何检查证明 resize 回调前读取旧导航状态。
驱动改为等待动画帧和实际可命中状态后，geometry-r1、product-final 与 product-runner 通过。
原 FAIL、日志和报告均保留，没有延长等待或削减原断言。

新建对话改为命令面板：已打开工作区、最近使用（未打开）、打开其他文件夹，支持方向键、Enter、Ctrl 1～9、Ctrl O、Ctrl N。
